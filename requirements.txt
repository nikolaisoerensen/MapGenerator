# --- Rechnen ---

# numpy BEWUSST NICHT auf der neuesten Version (2.5.1), sondern auf der
# neuesten, die numba akzeptiert. NICHT "vergessen zu aktualisieren".
#
# numba 0.66.0 ist seinerseits die neueste Version und verlangt NumPy <= 2.4.
# Mit numpy 2.5.1 schlaegt `import numba` fehl - und opensimplex FAENGT DAS AB
# und benutzt still seinen Attrappen-Dekorator statt des JIT. Gemessen am
# 2026-07-30, noise2array 256x256:
#
#     numpy 2.5.1 (numba tot)   0.3831 s
#     numpy 2.4.6 (numba aktiv) 0.0018 s      Faktor 213
#
# Es gibt keine Fehlermeldung, keinen Warnhinweis - nur ein Programm, das
# 36 % laenger rechnet (siehe die Messwerte beim numba-Eintrag unten).
#
# Wieder anheben, sobald numba NumPy 2.5 unterstuetzt. Pruefen mit:
#     .venv/Scripts/python.exe -c "import numba, numpy; print(numpy.__version__)"
# Schlaegt der Import fehl, ist numpy zu neu.
numpy==2.4.6
scipy==1.18.0

# numba schaltet den JIT-Pfad von opensimplex ein. Ohne es wird dessen
# @njit-Dekorator zu einer Attrappe und noise2array laeuft als reine
# Python-Schleife: gemessen 0.633 s je 256x256-Feld gegen 0.0012 s mit
# numba, also Faktor 528 - bei identischem Code und identischen Zahlen.
# Das war 36 % der gesamten Pipeline (14.1 s von 38.9 s bei 256 px),
# davon geology.layer_thickness allein 6.1 s und weather.temperature 4.7 s.
# Der erste Aufruf je Prozess kostet rund 2.5 s Kompilierung.
#
# Wird NIRGENDS direkt importiert - eine Textsuche nach "import numba" findet
# nichts. Deshalb dieser Hinweis: ohne ihn sieht das Paket wie eine Altlast
# aus und fliegt beim naechsten Aufraeumen raus.
